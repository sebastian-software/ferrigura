## 0. Summary

Agentflow is a Jison grammar with start conditions, a stateful DB class whose `getData()` is the render input (and which records diagnostics as a side effect), and a renderer that is the flowchart renderer's pipeline: `getData`, then the shared unified renderer on ELK layered, then the shared node, cluster, edge and label code. It adds one cluster shape (`flowGroup`), a colour palette keyed on the node's kind, and a configuration section of its own.

It shares the flowchart lexer almost verbatim (54 diff lines in the `%lex` sections of `flow.jison` and `agentflow.jison`), but not the flowchart DB (2,492 lines against 1,358 in `flowDb.ts`). It is not a new layout engine. It lays out with ELK (`elk.layered` by default), through the same ELK glue that `flowchart-elk` uses. `rendering-util/layout-algorithms/ddlt` is test scaffolding for swimlanes, not a layout. Agentflow does not use it.

Riskiest parts, in order:

1. **DB and lexer quirks that drop content silently.** A line whose text contains `direction TB` (or LR, BT, RL, TD) anywhere, including a label or a `%%` comment, produces no nodes and no edges and no error. A line that starts with `click` followed by a space does the same. Section 2.5, Q1 and Q2.
2. **`flowGroup` containers.** Ferrigura's `unified/clusters.rs:55-60` paints every cluster shape it does not know as `rect`, so a container that is not ported is drawn wrongly without any error. Probed: the palette rules of the reference beat the container's own `fill="none"` (section 6.5).
3. **Container and layout algorithms.** The reference runs `elk.box`, `elk.rectpacking`, `elk.stress` and the others, which change the layout (probed). Ferrigura falls back to layered (decision 0006). No fixture uses them, but the docs show them (sections 8.1 and 8.3).
4. **Configuration per diagram.** `theme`, `look` and `layout` resolve from the `agentflow` section (`config.ts:79-107`). The renderer also reads keys of the `flowchart`, `state` and `elk` sections. Decision 0009's typed views must include all of them (section 6.8).
5. **YAML metadata.** `@{ ... }` bodies go through js-yaml with `JSON_SCHEMA`, and a failure is re-positioned into source coordinates with an excerpt (`agentflowDb.ts:611-722`). A trailing-comma retry follows (`:383-391`). Ferrigura has a js-yaml port (`crates/ferrigura-syntax/src/yaml.rs`).
6. **Sanitising.** Labels, tooltips and link URLs pass through DOMPurify and `sanitizeUrl`. Probed: `<script>` is removed and `&` becomes `&amp;` in a label (section 2.4). Ferrigura has `sanitize.rs`, which covers the flowchart's uses.

## 2. Parser

### 2.1 Pipeline

1. `preprocessDiagram` (`preprocess.ts:58-86`) returns `raw`, `withComments` (directives removed, `%%` comments kept), `cleaned` (comments removed too, `cleanupComments`) and `frontmatterLineOffset`.
2. `Diagram.fromText` (`Diagram.ts:19-85`): the detector picks the type (`afDetector.ts:9-11`). The Jison object's `yy` is set to the DB (45-48), then `db.clear()` (49), `init(config)` (50), then the front matter title, if any (52-54).
3. For a diagram that keeps comments for its positions (`preserveCommentsWhenParsing`, `agentflowDb.ts:238`), the source is `withComments`, unless it is longer than `maxTextSize` (66-76). The text is then `encodeEntities(source) + '\n'` (77). The frontmatter offset goes to the DB (80-82).
4. `parser.parse(text)` (83) is the wrapper of section 1, which strips the horizontal whitespace after a closing `}` at the end of a line. The regex does not touch newlines, so the line numbers of the source stay right after a blank line (issue #56).
5. The grammar starts at `start: graphConfig document` (`agentflow.jison:322-324`). Each reduction calls the DB; section 3.1 lists the calls.

### 2.2 Lexer

All 18 start conditions are exclusive (`%x`, lines 37-54). A rule with no state prefix matches only in INITIAL, and a `<*>` rule matches in every state. Three conditions are declared and never entered: `vertex`, `href` and `shapeDataEndBracket`.

Jison's lexer takes the first rule that matches (`jison-lex` `regexp-lexer.js:382`, unless the `flex` option is set, and it is not). Quoted literal rules that end in a word character get `\b` appended (`lex-parser` 0.1.4, `lex-parser.js` case 31, unless `flex` is set). So `"flow"` matches the word `flow`, but not the start of `flowers`. Probed: `flowers`, `classroom`, `styled`, `defaultX`, `interpolated`, `endpoint` and `globalX` are all node ids (section 2.4).

### 2.5 Quirks to reproduce

These follow from the reference's code and were probed. The port has to reproduce them, because the differential compares what the DB holds.

- **Q1. A line that contains `direction TB`, `direction LR`, `direction BT`, `direction RL` or `direction TD` is lexed as a direction statement, and its content is dropped.** The rule `.*direction\s+XX[^\n]*` (`agentflow.jison:165-169`) matches anywhere on the line, including inside a label and inside a `%%` comment. No error is raised. Probed: `a["go direction LR now"] --> b` and `a --> b %% direction TB` both give an empty model.
- **Q2. `click` followed by whitespace swallows the rest of the line.** The `click` state (`:138-140`). Probed: `click --> b` gives an empty model. `call --> b` and `end --> b` are parse errors.
- **Q3. A top-level `direction` statement does nothing.** The `direction` alternative of `statement` (`:425`) has no action, and the DB has no setter that it reaches. Only the header and a container's own `direction` set a direction. Probed (`direction-top-level-overrides-header`).
- **Q4. The header direction is mapped by a regex.** `setDirection` (`agentflowDb.ts:902-920`) maps any string that contains `<`, `>`, `^` or `v` to RL, LR, BT or TB, and `TD` to `TB`. It leaves the others as written, so `BR` reaches the layout unchanged (probed: `dir` `BR`). The effect of `BR` on the layout is unverified.
- **Q5. The `linkStyle` bounds check never fires.** `numList` returns NUM token text (strings, `:615-619`), and the check at `agentflowDb.ts:850-855` and `:833-838` tests `typeof pos === 'number'`. An out-of-range index becomes a TypeError from `this.edges[pos].style` (`:860`). Probed. The bounds message in the code is not reachable.
- **Q6. Keyword rules match whole words only, because Jison adds `\b`.** Probed: identifiers that start with a keyword (Section 2.2). `end` and `global` have an explicit `\b` (`:145-146`).
- **Q7. The reserved id `connectors` is never a node.** `addVertex` returns for `connectors` (`agentflowDb.ts:440-442`), but the edge that names it is kept. Probed.
- **Q8. Shape names are case-sensitive and checked before anything else.** An uppercase or underscored shape is a parse error (`agentflowDb.ts:535-539`). A shape that is valid Mermaid but not allowed warns and renders as `roundedRect` (`shapes.ts:138-146`). A removed shape records an error and renders as `roundedRect` (`shapes.ts:127-136`). The metadata keeps the authored name.
- **Q9. `connector` is in the allowed set but is not a valid authored shape.** It is in `ALLOWED_SHAPES` (`shapes.ts:80`), and `isValidShape` rejects it (probed).
- **Q10. Container metadata `shape` and `label` have no effect.** A container's shape is `flowGroup` (`agentflowDb.ts:1827`), and its title is the grammar's title. Probed: `f@{ shape: subroutine, label: "Z" }` gives title `F` and shape `flowGroup`.
- **Q11. Duplicate container ids merge.** Members go to the first occurrence, the title and direction to the last (`agentflowDb.ts:1256-1276`). Probed.
- **Q12. A node in two containers stays in the first.** `makeUniq` (`:1252`) removes members that already belong to another container. Probed.
- **Q13. A containment cycle drops the nesting that closes it, and records a warning.** `agentflowDb.ts:1754-1785`. The edges are kept. Probed.
- **Q14. Edge ids skip a number when a pair repeats.** The first edge of a pair gets `_0`, the next gets `existing + 1` (`:763-776`), so the second is `L_a_b_2`. The index-based counter in `getData` (`:1864`) is never used, because the stored id wins. Probed.
- **Q15. Edge length is capped at 10** (`:758`). Probed.
- **Q16. The edge limit reads a snapshot.** `this.config` (`:215`) is refreshed in `clear` (`:1148`) and at a text-bearing `addVertex` (`:483`), and `addSingleLink` reads it (`:778`). Parse error text: `Edge limit exceeded`.
- **Q17. `__proto__`, `constructor` and `prototype` keys are removed from metadata at every depth** (`:124-139`).
- **Q18. Label text is sanitised with DOMPurify, and the markup rules depend on `securityLevel`** (`common.ts:56-83`). Probed: `<script>` removed, `&` escaped.
- **Q19. Click callbacks run only at `securityLevel: loose`** (`agentflowDb.ts:957-959`). Under the others the click only sets the class `clickable`. Probed.
- **Q20. `updateLink` adds `fill:none` to a style that has no fill** (`:862-867`). Probed.
- **Q21. The init hook mirrors two keys into the global configuration.** `init` sets `flowchart.arrowMarkerAbsolute` and `layout` (`diagram.ts:16-28`) through `setConfig`, which lasts until the next configuration update. It is re-run on every parse. Unverified beyond the code.

### 3.6 `getData` (`agentflowDb.ts:1696-1972`)

The render input. Steps, in order:

1. Collapsed containers (1706-1745): the members of a collapsed container are hidden, recursively with a cycle guard (1722-1740). `collapsedAncestorMap` redirects edges to the outermost collapsed container (1852-1856). An edge that becomes a self-loop by collapse is dropped; a real self-loop is kept.
2. Parents (1754-1785): a parent is set for each member, last container first. A parent that would close a cycle is refused with `CONTAINMENT_VIOLATION` (1775-1780).
3. Containers (1788-1834): a collapsed one is `collapsedGroup` with `containerType` in its metadata, `padding` 8 (1798-1816). An expanded one is `flowGroup` (`SUBGRAPH_TYPE_TO_SHAPE`, 1827), `isGroup` true, `padding` 8 (1818-1832).
4. Vertices (1836-1843): `addNodeFromVertex` (1613-1664). `padding` is `flowchart.padding || 8` (1636). `wrappingWidth` and `minWidth` come from `agentflow` (1659-1660). `look` is the top-level `look` (1842). A group member keeps its `metadata`.
5. Edges (1845-1901): `id` from `getEdgeId` (1864), `label` and `labelType`, `thickness` = stroke, `minlen` = length, `classes` = `edge-thickness-normal edge-pattern-solid flowchart-link` (1877; `invisible` gives no class), `arrowTypeStart` and `arrowTypeEnd` from `destructEdgeType` (1857; `none` for `arrow_open` and `invisible`). `curve` = the edge's `interpolate`, then the default one, then `flowchart.curve` (1894). `metadata` is copied (1897).
6. Shapes (1908): `normaliseNodeShapes(nodes, this)` maps each node to a supported shape and emits the two shape diagnostics (section 3.8).

## 4. Canonical model proposal

Two models fit the P1 conventions, and a third is optional. The DB model follows [../canonical-model.md](../canonical-model.md). The `getData` model is the layout input, and it is where the sanitising and the dropped fields show. The semantic projection is what downstream tooling reads.

### 4.1 DB model

```text
AgentflowDiagram { version: 1, direction, vertices, edges, subGraphs, connectors, classes, tooltips, diagnostics }
Vertex   { id, text, labelType, type, styles, classes, dir, link, linkTarget, tooltip, metadata, isConnector }
Edge     { id, isUserDefinedId, start, end, type, stroke, length, text, labelType, classes, style, interpolate,
           animate, animation, edgeSemantic, metadata }
SubGraph { id, nodes, title, labelType, dir, type, classes, metadata }
Diagnostic { id, severity, message, nodeId, edgeId }
```

| Field                    | Rule                                                                                                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `direction`              | The DB value. The header always sets it (TB when none is given, `:354`). `BR` is kept as written (Q4)                                                                                                                     |
| `vertices`               | In creation order, as the DB holds them, with container ids included, because the DB keeps them (`:2026-2032` removes them only for the semantic model). Decide (section 8.3, Q-a)                                        |
| `text`                   | The sanitised text, or `null`. A vertex without a bracket label keeps its id                                                                                                                                              |
| `type`                   | The authored shape after alias resolution: `square` for `[text]`, `round` for `(text)`, `roundedRect` for a metadata `task`, `subroutine` for `tool`. `null` for a bare id                                                |
| `metadata`               | JSON values as js-yaml gives them (numbers, booleans, arrays, objects, `null`), with the prototype keys removed (Q17)                                                                                                     |
| `domId`, `vertexCounter` | Left out. They are derived from a counter                                                                                                                                                                                 |
| `edges`                  | In creation order. `id` is always present (the user's, or `L_<start>_<end>_<n>`, Q14). `minlen` is the capped length (Q15)                                                                                                |
| `subGraphs`              | In completion order, as the DB holds them. A repeated id merges into its first position (Q11)                                                                                                                             |
| `connectors`             | The connector records, in creation order                                                                                                                                                                                  |
| `diagnostics`            | Ids, severity and the node or edge id. The messages are compared only if the port keeps them                                                                                                                              |
| Left out                 | `config`, except the keys the parse reads: `maxEdges` (`agentflowDb.ts:778`), `flowchart.inheritDir` (`:1214`) and `securityLevel` for clicks (`:957`). Also element mappings (section 8.3, Q-g), positions, the snapshot |

### 4.2 `getData` model (proposed for a second differential)

```text
AgentflowData { nodes: [LayoutNode], edges: [LayoutEdge], connectors: [Vertex] }
LayoutNode { id, label, labelType, parentId, padding, isGroup, shape, cssClasses, cssStyles, cssCompiledStyles,
             colorIndex, look, link, linkTarget, tooltip, wrappingWidth, minWidth, metadata }
LayoutEdge { id, start, end, label, labelType, thickness, minlen, arrowTypeStart, arrowTypeEnd, classes, pattern,
             curve, style, cssCompiledStyles, look, animate, animation, metadata }
```

`getData` is the model the renderer reads, so it is the one that shows `flowGroup`, the collapsed shape, the colour slots and the `padding` values (8 for containers and 15 for nodes, from `flowchart.padding`). `domId` is left out, because `render.ts:88-93` rewrites it per render.

### 4.3 Semantic projection (optional)

`getSemanticModel()` (section 3.7): `vertices` with `vertexKind`, `edges` with `edgeSemantic`, `subGraphs` with `direction`, `connectors`, `diagnostics`. It is what the conformance corpus asserts (`conformance/runner.ts`), so a port that has it can run those fixtures as they are.

### 4.4 Values that need a rule

- `label` may be sanitised in the DB, and the `getData` label is the same string. Probed for `<b>bold</b> & <script>x</script>`.
- `labelType` for a bracket label is `text` for `[text]` and `string` for `["text"]`. Probed: `a["A"]` gives `string`, `a[text]` gives `text`.
- A number as a metadata label (`label: 5`) goes to `sanitizeText`, which is typed for strings (`agentflowDb.ts:551`). The result is unverified.

## 6. Renderer

### 6.1 Pipeline

`draw` (`renderer.ts:17-56`) does these steps. The probed root is in section 6.2.

1. `setDiagramId(id)` (24). Node domIds are then prefixed with the diagram id (`render.ts:88-93`), so ids are `p0-agentflow-a-0` (probed).
2. `getData()` (31), which runs the shape normalisation and the colour slots (section 3.6).
3. `getDiagramElement(id, securityLevel)` (35, `insertElementsForSize.js:3-18`). The page must already hold the `svg` with that id: `getDiagramElement` selects it from `body`, or from the sandbox frame.
4. The layout data is completed (38-46): `type`, `layoutAlgorithm` (`getRegisteredLayoutAlgorithm(layout)`), `direction`, `nodeSpacing` and `rankSpacing` (both unused, section 6.8), `markers` = `point`, `circle`, `cross`, `hierarchy` (43), and `diagramId`.

`styles.ts` returns the palette rules (`genColor`, 42-107) followed by the static rules (121-279).

- **Kind rules** (58-79): for each kind, `[data-look="<look>"].node.af-kind-<kind>` sets `stroke` and `fill` on `rect`, `path` and `polygon`. The `.node` is in the selector on purpose (comment 64-68): the neo stylesheet's rules have the same specificity without it.
- **Container rules** (85-105): for each slot `i` below the container count, `[data-look="<look>"][data-color-id="color-<slot>"]` with `.cluster` and with `.node` (for the collapsed form) sets `stroke` and `fill` on `rect` and `path`.
- **Slots** (`colorSlots.ts`): kinds own slots 0 to 6 in this order: `tool` 0, `task` 1, `decision` 2, `input` 3, `refdoc` 4, `connector` 5, `action` 6 (lines 29-37). Containers cycle the slots from `KIND_COUNT` (7) upwards, modulo `paletteLength - 7`. Probed: a first container is `color-7`, a nested one `color-8`.
- **Fill and stroke without a palette** (`fill(slot)` at 51-52 and `border(slot)` at 50): with `bkgColorArray` missing, only the stroke is set.
- **Static rules** (121-279): the label fonts and colours, `.node rect` etc. with `fill: mainBkg`, `stroke: nodeBorder`, `stroke-width: <strokeWidth ?? 1>px` (142-150), `.edgePaths .path` (178-181), `.flowchart-link` (183-186), `.edgeLabel` (188-199), `.labelBkg` (202-204, `fade` via khroma), `.cluster rect` (206-210), `.flow-cluster rect` (212-216), `.node .collapsed-indicator` and `.collapsed-separator` (218-227), the tooltip (240-252), `.agentflowTitleText` (254-258), and `getIconStyles()` (278).
- **Cascade.** The palette rules, the static rules and the attributes compete. Probed (section 6.5): the palette rule wins over both attributes. Any port has to emit the same rules to get the same painted result.

## 8. Risks, effort, open questions

### 8.1 Risks

1. **The quirks of section 2.5 (Q1 to Q21).** They are reachable from ordinary text and produce empty or wrong models without an error. Q1 and Q2 drop whole lines. The differential catches them only if the port's corpus includes such lines. Mitigation: port the probes of section 2.4 as cases.
2. **`flowGroup` and the palette.** Missing the cluster shape is silent: `clusters.rs:55-60` paints `rect`. The palette rules beat the attributes (section 6.5), so the port has to emit the reference's CSS order and selectors, not only the attributes.
3. **Container and layout algorithms.** The reference's output for `elk.box` and `elk.stress` differs from layered (probed). The other algorithms (`elk.rectpacking`, `elk.force`, `elk.mrtree`, `elk.sporeOverlap`, `elk.radial`) were not probed. Ferrigura falls back (decision 0006). The docs show `elk.rectpacking`. The gap is user-visible, but no fixture hits it.
4. **Per-diagram configuration.** `theme`, `look` and `layout` resolve from the `agentflow` section. The renderer reads `flowchart`, `state` (`edges.js:934`) and `elk` keys as well. Decision 0009's typed views must include them, or the output differs for `state.arrowMarkerAbsolute`. The `init` hook (Q21) writes two more keys.
5. **Metadata YAML.** js-yaml with `JSON_SCHEMA`, the trailing-comma retry (`agentflowDb.ts:383-391`), the position translation (`:611-722`), and the excerpt text. If positions or messages are compared, the excerpt format has to match.
6. **Sanitising.** DOMPurify output is compared for labels and tooltips. Ferrigura's `sanitize.rs` covers the flowchart's paths. Agentflow also sanitises metadata labels (`:551`) and tooltips (`:949`), and uses `sanitizeUrl` for links (`utils.ts:250-262`). Check each.
7. **Keys that do nothing.** `nodeSpacing`, `rankSpacing` (probed). A port that gives them an effect would diverge.
