# P3: the remaining diagram types

P3 ports eight of the nine diagram families that Mermaid 12.2.0 has and ferrigura does not yet: agentflow, cynefin, radar, railroad, tree view, use case, venn and wardley. Swimlanes, the ninth, is a milestone of its own beside P3 (decision 2 below). With all nine, ferrigura covers the 33 families. For each: the parser and its DB, the canonical model, the specs and the renderer. The research per type is in `<type>/NOTES.md`, the parser decisions and the quirks each port reproduces in `<type>/PLAN.md`.

**Done when** each type passes its ported specs, `pnpm port:diff <type>` shows no difference on every collected input, and `pnpm port:geometry <type>` is within tolerance on every comparable fixture. Fixtures are excluded only with a named reason, as in M5, M6 and P2.

### Decided by Sebastian on 2026-10-18

1. **Symbol and fallback glyphs.** A small symbol face under the SIL Open Font License is bundled for the code points the bundled faces lack and the reference draws (the arrows of cynefin's subtitles first), embedded as a subset like the other faces and mapped in the harness on both sides. The unknown icon's `?` stays in `ArialMT, Arial`, as the reference writes it: the harness draws it with the machine's Arial on both sides.
2. **Swimlanes is a milestone of its own**, running beside P3: its layout is a port the size of ELK Layered. P3 is the other eight types.
3. **Collation.** The swimlane layout's `localeCompare` is a comparison of our own that gives ICU's root order exactly for ASCII; an ICU4X collator follows when ids outside ASCII need it.

### Decided by Sebastian on 2026-10-20

1. **Swimlanes is finished next**: its parser and its renderer, on the layout engine already ported. Done on 2026-10-20 ([swimlanes/PLAN.md](./swimlanes/PLAN.md)).
2. **handDrawn** comes later as a post-processing step over the finished SVG, not as a rough.js port inside each renderer. Until then its fixtures stay excluded.
3. **Themes** stay as they are (the two redux themes). Before porting Mermaid's classic themes, consider themes as sets of CSS custom properties, which the output already declares (decision 0007), in place of their colour computations.
4. **Math in labels** (KaTeX) is left out for now.
5. **Fallback faces**: emoji and the miscellaneous symbols and dingbats (U+2600-27BF) are added; CJK and Arabic are left out for now. Two faces, option B of [the fallback spike](./spikes/fallback-faces.md): Twemoji Mozilla 0.7.0 (COLRv0, colour) for the emoji with emoji presentation that it covers: 1,185 code points, 820,656 bytes. Noto Sans Symbols 2 (OFL) for the text-default symbols of U+2600-27BF that it covers: 252 code points, 56,636 bytes. Both sides of the comparison set the characters in these faces, as the arrows are set: the reference's page maps the families it names onto them, so the widths of the bundled faces on both sides match by construction (the advances of the spike's table, section 5). The licences and the provenance are in `crates/ferrigura-text/NOTICE.md`. Before a release, Safari 27 has to be checked for the COLRv0 emoji: WebKit 26.5 draws them, Safari 27 is not measured.
6. **Exclusions by coverage.** The geometry harness excludes a fixture only when its drawn text has a character that no bundled face covers, and the reason names the characters. The range list `UNCOVERED_SYMBOLS` is gone; the coverage is read from the bundled files (`tools/port/fonts/bundled.ts`). What no face draws stays excluded: CJK, kana, Arabic, the 34 emoji with emoji presentation that Twemoji lacks (for example U+1F6D8), and every symbol outside the faces. Characters in a tree view's box drawing are its syntax, not drawn text.

## Stages

1. **Research**: done, the nine `<type>/NOTES.md`.
2. **Registry scaffold**, one task, merged before the parsers.
3. **Parsers**, one task per type: model, parser and DB, specs, differential. Done on 2026-10-18 for the eight types: every collected input without a difference (agentflow 287, cynefin 125, radar 208, railroad 418, tree view 176, use case 291, venn 277, wardley 222), and each type's configuration section compared. Venn's DB keeps the sets in declaration order; the `Object.keys` order is the layout library's, and its port applies it.
4. **Layout engines and shared code**: the venn library (done on 2026-10-18: `ferrigura-venn`, exact on 447 cases captured in Chromium), the swimlane layout (its own milestone, on `sebastian/port-swimlanes`), agentflow's `flowGroup` cluster.
5. **Renderers**, after issue #4 (merged on 2026-10-19), each checked with `pnpm port:geometry <type>`. Done on 2026-10-19 for the eight types, one task per type, on the rules of [P3-RENDERERS.md](./P3-RENDERERS.md): every comparable fixture and probe within tolerance (257 in all; 6 handDrawn fixtures and 2 with emoji and symbols not compared), every differential without a difference, and the 28 032 corpus renders of the 24 types ported before P3 unchanged. The results per type are in [STATUS.md](./STATUS.md).

## Follow-ups

Found by the renderer tasks and left out of them, because each changes output that the corpus comparison kept fixed, or is outside a renderer:

- **Unified edges and clusters**: done on 2026-10-19. Every edge path of the unified renderer is `<diagramId>-<edge id>` and carries `data-points`; every type's collapsed group has its `data-color-id` before its `data-look` and its label group `style=""`. The note here had the label background backwards: the reference gives an edge label's background the label style (`style=""` for most), not `stroke: none`, which only a label without a background keeps; the text takes the style with `color` read as `fill`, so a coloured edge label is painted now. The `data-points` comparison of `port:geometry-flowchart` then found an extra point at the corner of a diamond, fixed with it: `question.ts` intersects with the diamond of the box it is given.
- **Numbers as text**: done on 2026-10-19. `number_text` writes `String(number)`, exponent notation and the even digit of a tie included, checked against Node on 5303 doubles in the tests and 3.5 million more. The pie's arcs were not rounded to three decimals as `d3-shape` 3.2.0 writes them, and had written `0` at twelve o'clock only because tiny numbers were cut; they are rounded now, and equal the reference's.
- **quadrant chart**: done on 2026-10-19, the faces are written once.
- **Shared text helpers**: done on 2026-10-19: `common::shown_text` and `common::template_text`, with the copies in railroad and cynefin as well. The copies read a named reference such as `#nbsp;` as its letters, where the reference shows the character (`probes/timeline/p-named-entities.mmd`).
- **Markup still different from the reference** (found by the comparison of the unified renderer's markup): the ER entities, requirement boxes and use case nodes write `data-color-id` after `data-look`, where the reference stamps it before; the class boxes write no `data-color-id`; a collapsed group's class is `node ` where the reference's is `node`. `data-points` equal the reference's for 3230 of 3524 edges; the others differ in the last digits where the edge's geometry does (at most 0.0066 px).
- **Text copies left**: the markup of a text (`decode_entities(escape(text))`) is copied in timeline, treemap, wardley, quadrant chart and cynefin; agentflow's `js_number_text` in `ferrigura-syntax` writes numbers without exponent notation, unlike `number_text`.
- **Configuration layer**: the typed configuration replaces a value of the wrong type by the schema default before a renderer sees it, where the reference keeps it (tree view's `extensionIcons` with a number fails the reference's render; cynefin's `boundaryAmplitude: null`).
- **Default theme**: railroad and radar keep the default theme's values that the reference merges under the active theme as tables of their own; shipping the default theme's variables would replace them.
- **Harness**: the geometry harness compares geometry, not the style sheet's declarations; railroad's colour fallback was caught by a spec only.
- **Not reproduced**: agentflow's `inheritDir` with a repeated container, a non-text edge interpolation, `animate` other than `true`, and its diagnostics in the render; use case's mutation check of the quirk tests was not run.
