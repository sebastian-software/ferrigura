# P2 renderers: how a renderer task works

The working rules of [M6-RENDERERS.md](./M6-RENDERERS.md) apply to the P2 renderer tasks unchanged: what exists, how a renderer is checked with `pnpm port:geometry <type>`, the gates, the rules of the branch and the report. The research is in `docs-port/<type>/NOTES.md` (the renderer section) and the decisions in [P2-PLAN.md](./P2-PLAN.md). What P2 adds:

- **The scaffold**: every P2 type has its renderer stub in `crates/ferrigura-render/src/<module>/mod.rs` and its arm in the facade; its parser and canonical model are ported, with no difference from the reference (`pnpm port:diff <type>`).
- **Math**: where the reference computes with `Math.sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `log`, `pow` or `hypot`, use `ferrigura_jsmath` (its default functions give Chromium's results bit for bit), not the `f64` methods, which differ in the last bit for a few percent of inputs.
- **Text boxes**: `getBBox` and `getBoundingClientRect` of SVG text are, across, the union of the advance and the glyphs' ink (`ferrigura_text::measure_box`, `measure_line_box`); `getComputedTextLength`, wrapping and anchoring use the advance (`measure`, `measure_line`). `common::text` (`calculateTextDimensions`) already uses the box.
- **Fonts the reference names itself**: the harness page maps `trebuchet ms`, `verdana`, `arial`, `Helvetica Neue`, `Helvetica` and `Open Sans` onto the bundled face (`MAPPED_FAMILIES` in `tools/port/geometry/common.ts`), so text that the reference measures in one of them is measured in Lexica on both sides. ferrigura measures with the bundled face wherever the reference names a font of its own.
- **Screen and container**: the harness page's viewport and screen are 1200 by 900 px, and its body has no margin. A renderer that reads the screen or its container takes 1200 px unless the configuration sets a width.
- **Layout engines**: cose-bilkent and fcose (`ferrigura-cose`) and the tidy tree are separate tasks; the mindmap and architecture renderers start when their engine is merged.
- **Worktree setup**: after `pnpm install --frozen-lockfile --prefer-offline --ignore-scripts`, build the reference bundle from the branch's sources with `pnpm build:esbuild` (a few seconds; a bundle copied from another checkout can be older than the sources, and then the harness compares against an old reference, and the ELK capture hook is missing), then run `pnpm exec husky`, so that the pre-commit hook runs; commit with the hooks enabled (never `core.hooksPath=/dev/null` or `--no-verify`).
- **Status**: `pnpm port:status` keeps a differential cell when the checkout has no summary for it, so it is safe to run in a task worktree; check its diff before committing it.
